# 같이 하기 2단계: 섬 공동 목표 — 설계

- 날짜: 2026-11-10
- 앞 단계: [같이 하기 1단계 (방·서로 보이기·채팅)](2026-11-07-multiplayer-foundation-design.md)
- 다음 단계(이번 범위 밖): 협동 보스 낚시

## 1. 왜, 무엇을

지금 방은 "같은 공간에서 각자 낚시"라서 같이 할 이유가 없다. 2단계는 방 사람들이 **함께 섬을 바꾸는** 목표를 준다.

성공 기준 (스터디 모임 5~15명, 접속 시간이 제각각, 대화하며 플레이):
- 첫 모임 안에 건물 하나가 눈에 띄게 바뀐다.
- 가끔 오는 사람도 들어오자마자 보탤 일이 있고, "내가 없는 동안 생긴 일"을 본다.
- 서로 말을 걸 계기가 생긴다 (남은 재료, 못 연 구역, 풍어 시작 시점).
- 보상의 중심은 코인이 아니라 **섬의 변화와 사람의 흔적**이다.

외부 리뷰(Codex, 6/10)에서 받은 지적을 반영했다: 일일 만료 → 계속 남는 주문서, 게이지 감쇠 → 모아 두기, 완성 보너스 코인 → 없앰, 체감 약한 보너스(−10%) → 눈에 띄는 보너스, 풍어가 동굴 전설을 줄이던 문제 → 모든 희귀도에 고르게.

혼자 하기는 바뀌지 않는다. 아래 모든 것은 방에 들어가 있을 때만 있다.

## 2. 플레이어 경험

### 2.1 주민과 시설

| 주민 | 자리 | 짓는 시설 | 주문서 성격 |
|---|---|---|---|
| 등대지기 할아범 (`keeper`) | 선착장 옆 | 등대 (`lighthouse`) | 구역 줄이 많다 ("해변 물고기 아무거나") |
| 식당 주인 (`cook`) | 어시장 옆 | 바닷가 식당 (`diner`) | 종 지정 줄이 많다 ("투덜이 우럭 2마리") |
| 축제 꼬마 (`kid`) | 광장 | 축제 무대 (`stage`) | 희귀도 줄이 섞인다 ("희귀 이상 1마리") |

- 주민은 캐릭터 파츠를 고정한 모습이고, 이름표와 주문서가 있을 때 📜 말풍선이 뜬다. 다가가면 "E 주문서 보기".
- 시설은 단계 0~3. 0단계는 "공사 예정" 팻말과 기둥, 단계마다 모습이 늘어난다. 단계가 오르는 순간 1~2초 반짝임·먼지 연출.
- 시설 앞 **기여자 팻말**(E): 단계별 기여자 닉네임.
- 3단계 이후에도 주문서는 계속 나오고, 한 장 채울 때마다 광장 장식(깃발·등불·화분)이 하나 늘어난다 (최대 24, 자리는 고정 목록).

### 2.2 주문서

- 주민마다 주문서가 **늘 한 장** 있다. 날짜로 사라지지 않는다. 다 채우면 바로 다음 장.
- 한 장은 2~3줄, 줄 종류:
  - `species`: 그 종 (일반 등급만 지정)
  - `zone`: 그 구역에 사는 아무 물고기 (잡어 제외)
  - `rarity`: 그 희귀도 **이상** 아무거나
- 크기: 주민별 n번째 장(0부터)은 물고기 `min(5 + n, 10)` 마리. 6마리 이하면 2줄, 넘으면 3줄.
- 쓸 수 있는 구역은 그 주민 시설 단계를 따른다:
  - 0단계: 해변 `species`·`zone` 줄만
  - 1단계: + 연못/암초, `rarity` 줄(희귀 이상, 1마리)
  - 2단계 이상: + 동굴 `zone` 줄(1마리), `rarity` 줄 최대 2마리
  - 주민 성격(위 표)은 허용된 줄 종류 중 무엇이 더 자주 나오는지만 바꾼다.
- 그 구역을 아직 못 연 사람은 그 줄을 못 채운다 — 연 사람에게 부탁할 일이 생긴다.
- 시설 단계 n → n+1 에 필요한 완성 주문서 수: 1, 2, 3 (주민당 6장, 그 뒤는 장식).
- 주문서는 "방 id + 주민 + 장 번호" 씨앗으로 결정적으로 만든다.

### 2.3 납품과 보상

- 주문서 창에서 줄마다 진행("1/2")과, 내 보관함 중 그 줄에 맞는 물고기만 보인다. 한 마리씩 [납품].
- 서버가 받아 주면(`delivered ok`) 그때 보관함에서 빼고 **판매가 × 1.2** 코인을 준다.
- 맞는 물고기가 없으면 어느 구역에서 잡히는지 안내한다.
- 주문서 완성: 시설 진행, 방 전체 큰 알림, 소식 기록, 팻말에 그 장 기여자 추가. **완성 보너스 코인은 없다.**
- [🙋 도움 요청]: 채팅에 "OO님: 등대에 투덜이 우럭 2마리 필요해요!" (남은 재료를 서버가 붙인다).

### 2.4 시설 보너스 (방에 있을 때만, 단계는 누적)

| 시설 | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| 등대 | 가짜 입질 수 절반 (내림) | 가짜 입질 없음 | 입질 대기 × 0.7 |
| 식당 | 식당에서 E: 식사 연출 뒤 체력 가득 (사람마다 10분에 한 번) | 10초 안에 둘 이상 식사하면 그 사람들 10분간 체력 소모 × 0.75 | 메뉴판에 최근 납품된 물고기 이름 (꾸밈) |
| 무대 | 무대 위 둘 이상이 이모트하면 동시에 맞춰 춤추고 꽃가루 (꾸밈) | 풍어 게이지 충전 × 1.2 | 풍어 시간 +60초, 불꽃놀이 |

### 2.5 풍어 게이지

- 방에서 누가 잡든 오른다: 잡어 +3, 일반 +5, 희귀 +8, 에픽 +12, 전설 +20.
- **줄지 않는다.** 100이 되면 "풍어 준비 완료"로 멈춰 모아 둔다.
- 아무나 축제 꼬마에게 E → 10초 예고("🎉 풍어 축제 10초 전!") → **풍어 180초** (무대 3단계면 240초) → 끝나면 0부터.
- 준비 완료이거나 예고·풍어 중엔 오르지 않는다.
- 풍어 효과: 희귀·에픽·전설 가중치 모두 × 1.5 (동굴 비율이 그대로라 전설이 줄지 않는다), 입질 대기 × 0.5, 바다 반짝임.

### 2.6 섬 소식

- 방에 들어오면, 이 방에서 마지막으로 본 시각 이후 소식을 최대 5줄 카드로 보여 준다 (없으면 안 뜬다).
- 소식 종류: 주문서 완성("OO·△△님 덕에 등대 2단계 완성!"), 장식 추가, 풍어 시작.
- 마지막으로 본 시각은 방 이름별로 localStorage.

## 3. 서버 (방 Durable Object)

### 3.1 저장 (키별 `ctx.storage.put`, 바뀔 때만)

```ts
// 'village'
type VillageSave = {
  villagers: Record<VillagerId, {
    stage: 0 | 1 | 2 | 3
    done: number              // 완성한 주문서 수 (단계·장식 계산)
    order: Order
  }>
  plaques: Record<VillagerId, string[][]>   // [단계 1..3] → 기여자 닉네임
  decorations: number
  recent: { device: string; fishId: string }[] // 최근 받은 납품 100개 (중복 방지·끊김 복구)
}
type Order = {
  no: number                  // 주민별 장 번호
  lines: { kind: 'species' | 'zone' | 'rarity'; key: string; need: number; got: number }[]
  contributors: { device: string; nick: string }[]
}
// 'gauge'
type GaugeSave = { value: number; ready: boolean; countdownEndsAt: number | null; festivalEndsAt: number | null }
// 'news'  — 최근 30개
type News = { at: number; kind: 'built' | 'decor' | 'festival'; villager?: VillagerId; stage?: number; names: string[] }
```

- `village` 가 없는 방(1단계 때 만든 방 포함)은 빈 마을로 시작한다.
- 풍어 끝·예고 끝은 알람 없이 **시각으로 판정**한다 (메시지가 올 때 확인) — 조용한 방은 잠들어 요금이 들지 않는다.

### 3.2 메시지 (`protocolVersion` 1 → 2, 다르면 기존 `version` 오류 → "새로고침")

기기 → 서버:

| 메시지 | 내용 | 서버 속도 제한 |
|---|---|---|
| `hello` + `device` | 기기 고정 id (16자 hex, localStorage `fishing-island-device-v1`) | — |
| `catch {speciesId}` | 잡았을 때. 희귀도는 서버가 종으로 찾는다 | 2초에 1번 (넘치면 무시) |
| `deliver {villager, no, line, speciesId, fishId}` | 한 마리 납품 | 초당 2번 |
| `festival {}` | 풍어 시작 (준비 완료일 때만) | 2초에 1번 |
| `help {villager}` | 도움 요청 | 10초에 1번 |

서버 → 기기:

| 메시지 | 받는 사람 | 내용 |
|---|---|---|
| `welcome` + `village`, `gauge`, `news`, `now`, `mine` | 본인 | 전체 상태, 서버 시각, `mine`: 이 기기의 최근 받은 납품 fishId (끊김 복구) |
| `village {village, event?}` | 모두 | 납품·완성 때마다 전체 + 사건(알림용) |
| `gauge {value, ready, countdownEndsAt, festivalEndsAt, now}` | 모두 | 바뀔 때마다 |
| `delivered {fishId, ok, reason?}` | 본인 | 거절 이유: `stale`(지난 장) / `mismatch` / `full` / `dup` |
| `help {id, villager, need}` | 모두 | 채팅 줄로 보인다 |

### 3.3 판정

- `deliver`: 장 번호가 지금 것과 다르면 `stale`. 종이 없거나 줄 조건에 안 맞으면 `mismatch`. 줄이 다 찼으면 `full`. 같은 기기·fishId 가 `recent` 에 있으면 `dup`(ok 로 다시 알려 준다).
  - DO 는 메시지를 하나씩 처리하므로 마지막 칸 동시 납품은 먼저 온 쪽만 받는다.
  - 마지막 줄이 차면: 단계·팻말·장식·소식 갱신 → 다음 장 생성 → 저장 → 방 전체에 `village`.
- `catch`: 준비 완료·예고·풍어 중이면 무시. 무대 2단계 이상이면 × 1.2. 100 이상이면 `ready`.
- 잡았다는 말은 믿는다 (스터디 모임 용도, 속도 제한으로 막는다).

### 3.4 코드 위치

- `server/src/village.ts`: 위 판정과 저장. `room.ts` 는 메시지를 넘기고 결과를 보낸다.
- 판정 본체는 `src/game/logic/` 의 순수 함수를 서버와 기기가 같이 쓴다.

## 4. 기기 (클라이언트)

| 위치 | 하는 일 |
|---|---|
| `data/village.ts` | 주민·자리·시설 단계, 주문서 크기·구역 규칙, 게이지 점수, 풍어 시간·효과, 보너스 표, 장식 자리 |
| `logic/villageOrders.ts` | `makeOrder(seed, villager, no, stage)`, `lineAccepts(line, species)`, `applyDelivery(save, …)` → 결과·사건 |
| `logic/festivalGauge.ts` | `addCatch`, `startFestival`, `gaugeStatus(save, now)` |
| `logic/villageBonus.ts` | 시설 단계 + 풍어 상태 → `{ nibbleScale, biteWaitScale, rarityMul, staminaScale }`. 기존 입질·확률·체력 함수가 이 값을 인자로 받는다. 방 밖이면 보정 없음 |
| `logic/netProtocol.ts` | 새 메시지 타입과 검사 함수 |
| `stores/villageStore.ts` | 서버 마을 상태, 서버 시각 차이, 납품 대기 중 fishId, 소식 본 시각 |
| `scene/village/*` | 주민, 등대·식당·무대(단계별), 장식, 풍어 연출 |
| `ui/OrderPanel.tsx` | 주문서 창 (새 session mode `order`) |
| `ui/VillageBar.tsx` | 목표 바 아래: 게이지 막대 + 가장 적게 남은 줄 한 줄 |
| `ui/NewsCard.tsx` | 들어올 때 소식 카드 |

- 잡을 때 `catch` 를 보낸다 (방에 있을 때만).
- 납품은 `delivered ok` 가 와야 보관함에서 빠진다. 끊기면 대기 중 표시를 지우고, 다시 들어올 때 `welcome.mine` 으로 이미 받은 것을 정리하고 코인을 준다.
- 풍어 중 연결이 끊기면 그 자리에서 풍어 효과를 끈다.

## 5. 테스트

- 순수 함수: 같은 씨앗 → 같은 주문서 / 단계별 구역 규칙 / 첫 장 5마리 / 줄 판정(종·구역·희귀도 이상, 잡어 제외) / `stale`·`full`·`dup` / 완성 → 다음 장·단계·팻말·장식·소식 / 게이지(감쇠 없음, 준비·풍어 중 안 오름, 무대 배율, 풍어 끝) / 보너스(동굴 풍어 때 전설 비중이 줄지 않음, 방 밖이면 보정 없음).
- 서버: 동시 납품 먼저 온 쪽만, 속도 제한, 빈 마을로 시작, 버전 1 거절.
- 기기 스토어: ok 와야 빠짐·코인, 거절·끊김이면 물고기 남음, `mine` 복구.
- 헤드리스 Chrome 두 창 `tools/village-check.mjs`: 주민 창 → 납품 → 상대 화면 진행 → 완성 → 시설 모습·소식 → 게이지 채움 → 풍어 시작이 두 화면에.

## 6. 만드는 순서와 배포

1. 데이터·순수 함수 → 2. 프로토콜·서버 → 3. 기기 스토어 → 4. 주민·주문서 창 → 5. 시설 모습 → 6. 게이지·풍어 → 7. 보너스 연결 → 8. 소식·도움 요청 → 9. 끝까지 확인.

배포는 **서버 먼저**(`npm run server:deploy`), 그다음 main push(Vercel). 그사이 예전 화면은 버전 오류로 "새로고침" 안내를 받는다.

## 7. 이번 범위 밖

협동 보스 낚시, 순위표, 주문서 강제 인원 조건, 방장 권한, 서버가 낚시 결과를 직접 굴리는 것(잡았다는 말은 믿는다).

# 같이 하는 낚시섬 1단계: 암호 방 · 서로 보이기 · 채팅

## 큰 그림

낚시섬을 여러 명이 동시에 접속하는 게임으로 바꾼다. 세 단계로 나눠 차례로 만든다.

1. **기반 (이 문서)**: 암호 방에 모여 서로의 캐릭터·동작을 보고 채팅한다.
2. **섬 공동 목표 (다음 문서)**: 방 사람들이 함께 모은 물고기·코인으로 섬 시설을 같이 짓는다. 방마다 진행을 Supabase DB 에 저장한다.
3. **협동 보스 낚시 (그다음 문서)**: 여러 명이 동시에 감아야 잡히는 대왕 물고기. 방의 한 명(호스트)이 보스 상태를 계산하고 나머지는 입력만 보낸다.

혼자 하는 진행(코인·도감·장비·어항)은 지금처럼 각자 기기에 저장하고 그대로 둔다. 1단계는 서버에 아무것도 저장하지 않는다.

## 사용자가 정한 것

- 같이 보이는 것: 다른 사람 캐릭터(옷차림·닉네임), 위치, 동작(걷기·앉기·먹기·감정 표현·낚시), 채팅.
- 서버: Supabase Realtime (presence + broadcast). Vercel 은 정적 배포 그대로.
- 방: 방 이름 + 암호를 아는 사람끼리만 같은 섬에서 만난다.

## 방과 암호

- 시작할 때 고르는 창: **혼자 하기** / **방 만들기·들어가기** (방 이름, 암호, 닉네임 입력).
- 채널 이름 = `island:` + SHA-256(`rinfish|` + 방 이름 + `|` + 암호) 의 앞 32자 (16진수). Web Crypto `crypto.subtle.digest` 로 만든다.
  - 암호를 모르면 채널 이름을 알 수 없다. Supabase Realtime 은 채널 목록을 주지 않는다.
  - 방 이름은 앞뒤 공백을 지우고 소문자로 맞춘다. 암호는 그대로(대소문자 구분).
  - 방 이름 1~20자, 암호 4~32자.
- 공유 링크 `?room=<방 이름>` 에는 **방 이름만** 넣는다. 링크로 들어오면 방 이름이 채워진 입장 창이 뜨고 암호는 직접 입력한다. 화면 위 방 배지에 "링크 복사" 버튼.
- 틀린 암호는 서버 없이 구분할 수 없다(빈 다른 섬에 들어간다). 들어갔는데 아무도 없으면 "아무도 없어요. 처음 만든 방이 아니라면 암호를 확인해 보세요" 안내를 한 번 띄운다.
- 마지막으로 들어간 방 이름·닉네임은 기기에 저장(`fishing-island-net-v1`). 암호는 저장하지 않는다. 새로고침하면 입장 창에 방 이름이 채워져 있다.
- 인원: 방마다 최대 20명. 들어갔을 때 presence 인원이 이미 20명 이상이면 "방이 꽉 찼어요" 안내 후 혼자 하기로.

## 닉네임

- 1~10자, 앞뒤 공백 제거, 줄바꿈·제어문자 제거. 같은 방에 같은 닉네임이 있어도 막지 않는다 (머리 위 이름표에 그대로 표시).
- 설정 창에서 바꿀 수 있고, 바꾸면 presence 를 다시 보낸다.

## 주고받는 것

### presence (들어올 때, 바뀔 때)
`{ id, nick, look, joinedAt }`
- `id`: 탭마다 새로 만드는 무작위 id (기존 `logic/id.ts`).
- `look`: `CharacterLook` 그대로. 받는 쪽은 기존 `normalizeLook` 으로 검사한다.
- `joinedAt`: 3단계 호스트 고르기에 쓴다 (가장 먼저 온 사람).

### broadcast `state` (초당 최대 10번, 바뀐 게 없으면 1초마다 1번)
`{ id, t, p: [x, y, z], yaw, speed, pose, action, rod }`
- `t`: 보낸 사람 시각(ms). 순서 확인과 보간에만 쓴다.
- `pose`: 기존 `CharacterPose` 문자열. 받는 쪽은 값이 그 목록에 있는지만 보고 그대로 모델에 넘긴다.
- `action`: 기존 `PlayerAction` (점프·감정 표현·먹기).
- `rod`: 낚시 중이면 `{ bobber: [x, y, z] }`, 아니면 `null`. 받는 쪽은 낚싯대 + 찌 + 줄만 그린다.
- 숫자는 소수 둘째 자리까지 반올림해 보낸다.

### broadcast `chat`
`{ id, text, t }` — 1~60자, 줄바꿈·제어문자 제거. 보내는 쪽에서 1초에 1번으로 제한하고, 받는 쪽도 같은 사람이 1초 안에 또 보낸 건 버린다.

모든 받은 메시지는 `logic/netMessages.ts` 의 검사 함수로 모양·범위(좌표는 섬 반경 + 여유 안, 글자 수 등)를 확인하고 틀리면 버린다.

## 다른 사람 그리기

- 받은 state 를 사람마다 최근 몇 개 쌓아 두고, **지금 - 120ms** 시점을 두 state 사이에서 보간해 그린다 (위치 선형, yaw 는 짧은 쪽으로 회전). 새 state 가 1초 넘게 안 오면 마지막 자리에 멈춰 서 있다.
- presence 에서 나가면 바로 지운다. state 만 5초 넘게 안 오면 숨긴다.
- 모델은 지금 플레이어가 쓰는 `PlayerModel` 을 `look`·`pose`·`action` 만 받아 그리게 해서 재사용한다 (물리 몸 없음, 서로 통과).
- 머리 위 이름표(닉네임), 채팅 말풍선(5초).
- 폰(quality low)에서는 가까운 10명까지만 그린다.

## 화면

- **입장 창**: 혼자 하기 / 같이 하기(방 이름·암호·닉네임). 로딩 화면이 끝난 뒤 뜬다.
- **방 배지** (화면 위): `🔒 방 이름 · 👥 3명` + 링크 복사 + 나가기(혼자 하기로).
- **채팅**: 왼쪽 아래 최근 30줄(몇 초 뒤 흐려짐). Enter 로 입력 열기·보내기, Esc 로 닫기. 입력 중에는 이동 키가 먹지 않는다. 폰은 💬 버튼.
- **알림**: "○○님이 들어왔어요 / 나갔어요" 를 기존 notice 로.

## 연결 끊김·키 없음

- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 가 없으면 입장 창에서 "같이 하기"를 숨기고 지금처럼 혼자 하기만.
- 연결이 끊기면 배지에 "다시 연결 중…" 을 띄우고 Supabase 클라이언트의 자동 재연결에 맡긴다. 다시 붙으면 presence 를 다시 보낸다. 끊긴 동안에도 혼자 게임은 계속된다.

## 보안에 대해

로그인이 없어서, 채널 이름(=암호에서 만든 값)을 아는 사람은 위치·채팅을 조작해 보낼 수 있다. 스터디 규모라 감수한다. anon key 는 원래 공개용 값이다. 1단계는 DB 를 쓰지 않으므로 DB 접근 권한은 열지 않는다.

## 코드 나누기 (scene/ui → stores → logic → data)

- `data/net.ts`: 숫자들 (보내는 빈도, 보간 지연, 인원 제한, 글자 수, 폰에서 그릴 인원).
- `logic/roomKey.ts`: 방 이름·암호 정리, 채널 이름 만들기, 입력 검사. 테스트.
- `logic/netMessages.ts`: presence/state/chat 만들기·검사, 숫자 반올림. 테스트.
- `logic/interpolate.ts`: 받은 state 버퍼에서 지금 그릴 자리 계산. 테스트.
- `logic/chat.ts`: 글자 정리, 보내기·받기 속도 제한. 테스트.
- `net/realtime.ts`: Supabase 채널 열기/닫기, presence track, broadcast 보내기·받기. 화면·스토어를 모른다.
- `stores/netStore.ts`: 연결 상태, 방 정보, 다른 사람 목록(presence + state 버퍼), 채팅 기록. 테스트(가짜 채널).
- `net/NetBridge.tsx`: 내 상태를 읽어 보내고(useFrame), 받은 걸 스토어에 넣는 연결부.
- `scene/RemotePlayers.tsx`, `scene/RemotePlayer.tsx`: 다른 사람 그리기.
- `ui/LobbyPanel.tsx`, `ui/RoomBadge.tsx`, `ui/ChatBox.tsx`.
- 기존 수정: `PlayerModel` 을 플레이어 전용 상태 없이도 그릴 수 있게, `Player` 가 지금 pose·찌 위치를 sessionStore 에 내놓게, 키 입력이 채팅 중엔 멈추게, 설정에 닉네임.
- 새 의존성: `@supabase/supabase-js`.

## 확인 방법

- 단위 테스트: 위 logic 파일들, netStore(가짜 채널로 들어오기·나가기·state·chat).
- 키 없는 빌드에서 혼자 하기가 지금과 똑같이 되는지.
- 키를 받은 뒤: 헤드리스 Chrome 두 개를 같은 방·같은 암호로 띄워 서로 보이는지·채팅이 가는지, 다른 암호면 안 보이는지 스크린샷으로 확인.

## 사용자가 할 일

1. supabase.com 가입 → 새 프로젝트(무료).
2. Project Settings → API 의 Project URL, anon public key 를 전달 (로컬 `.env.local` 에 넣는다).
3. Vercel 프로젝트 환경변수에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 추가 후 재배포.

## 2·3단계를 위한 자리

- presence 의 `joinedAt` 으로 호스트(가장 먼저 온 사람)를 정할 수 있다.
- broadcast 이벤트 이름은 `state`·`chat` 외에 `boss:*`, `goal:*` 를 쓴다.
- 방 id(채널 이름의 해시)가 2단계 DB 의 방 키가 된다. 암호를 아는 사람만 그 키를 안다.
